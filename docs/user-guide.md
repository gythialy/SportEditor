# 使用手册

本手册面向最终用户，说明 SportEditor 的安装、激活、四种步数修改方式、每日上限、设置项与故障排查。内容按当前源码行为编写；开发与实现细节见 [开发文档](development.md)。

## 一、适用环境与前置条件

| 条件 | 要求 |
| --- | --- |
| 系统 | Android 8.0（API 26）及以上 |
| 架构 | arm64 设备 |
| Root | 已 root（Magisk / KernelSU / APatch 任一方案） |
| Hook 框架 | LSPosed 2.0+，需支持 libxposed API 101 / 102 的发行版，例如 Vector、JingMatrix 维护版；官方 1.9.2 只支持 API 100，不能使用 |
| 网络 | 仅「检查更新」需要联网访问 GitHub Releases API；修改步数本身不需要网络 |

模块声明在 [module.prop](https://github.com/gythialy/SportEditor/blob/main/app/src/main/resources/META-INF/xposed/module.prop) 中：`minApiVersion=101`、`targetApiVersion=102`。应用内首页顶栏的「已连接 / 未连接」显示的就是与框架服务的连接状态，点开可查看框架名称、版本和 API 版本。

> **提醒**：本模块会改写目标应用从系统计步传感器读到的数值，只在 LSPosed 作用域内、且你手动打开开关的应用中生效。请先用自己账号的小号或测试环境验证效果。

## 二、安装与激活

1. **安装 APK**：从 [GitHub Releases](https://github.com/gythialy/SportEditor/releases) 下载最新 APK 并安装到手机。签名与发布通道见 [发布与签名](release.md)。
2. **启用模块**：打开 LSPosed / Vector 管理器 →「模块」，勾选启用「运动修改器」。
3. **勾选作用域**：在模块详情的作用域中勾选微信、支付宝、QQ、微博中你要修改的应用。模块的 [scope.list](https://github.com/gythialy/SportEditor/blob/main/app/src/main/resources/META-INF/xposed/scope.list) 已预置这四个包名（`staticScope=true`），不同管理器版本仍可能需要你在界面上确认勾选。
4. **重启目标应用进程**：到系统设置里对目标应用执行「强行停止」，然后重新打开它。首次启用模块、或更新模块版本后必须做这一步——Hook 只在目标进程启动时安装；仅把应用划到后台、或冻结后再解冻不会重新注入。
5. **配置规则**：打开「运动修改器」，在首页对应应用卡片上打开开关（**默认全部关闭**），展开卡片选择修改方式、步数和每日上限。
6. **查看结果**：重新进入目标应用的运动页面查看。若数据没有变化，先用首页连接状态和「设置 → 诊断」定位问题（见第八节）。

如果框架服务尚未连接，首页会显示「未连接」并提示「在 LSPosed 中启用本模块，勾选目标应用，然后重启本应用」。此时仍可编辑配置，设置会暂存在本机，连接恢复后自动同步。

## 三、四个应用独立配置

每张卡片互不影响：开关、修改方式、步数、每日上限都是独立保存的。卡片右上角「更多 → 重置」可以单独把该应用恢复为默认值，操作需要二次确认；没有全局重置。未安装的应用会标注「未安装」，但不影响提前配置。

| 应用 | 包名 | 默认开关 | 默认方式 / 数值 | 默认基础上限 | 界面推荐方式（★） |
| --- | --- | --- | --- | --- | --- |
| 微信 | `com.tencent.mm` | 关闭 | 倍率 ×50 | 20,000 | 倍率；**不提供「固定」** |
| 支付宝 | `com.eg.android.AlipayGphone` | 关闭 | 倍率 ×10 | 15,000 | 自动 |
| QQ | `com.tencent.mobileqq` | 关闭 | 倍率 ×100 | 80,000 | 增加 |
| 微博 | `com.sina.weibo` | 关闭 | 倍率 ×100 | 80,000 | 增加 |

微信的「固定」选项不会出现在方式列表中：微信运动按增量同步，固定上报同一个值无法产生增量。旧版本保存的微信固定配置会被自动回退为默认倍率。

## 四、四种修改方式怎么选

界面「修改方式」的显示名为 **倍率 / 增加 / 自动 / 固定**（卡片摘要分别显示 `×N`、`+N`、`自动 +N`、`固定 N`；实现中称 MULTIPLY / ADD / AUTO / REPLACE）。它们决定的是**当天允许新增多少步**，而不是把系统传感器的绝对计数改成一个固定数。

| 方式 | 含义 | 可填数值 | 何时选 |
| --- | --- | --- | --- |
| 倍率 | 当日增量 = 当日真实步数增量 × 数值 | 1–10,000 | 想让真实步行按比例放大；微信推荐 |
| 增加 | 当日增量 = 当日真实步数增量 + 数值（该偏移每天只加一次） | 1–9,999,999 | 想保留真实步数并加一个固定尾巴；QQ、微博推荐 |
| 自动 | 按回调序号递增：第 1 次 +0、第 2 次 +N、第 3 次 +2N……直到当日上限 | 1–9,999,999 | 不依赖真实步数、希望数值逐步增长；支付宝推荐 |
| 固定 | 当日上报增量恒为 N，与真实步数无关 | 1–9,999,999 | 希望每天显示大致相同的步数；微信不可用 |

具体例子（均受当日上限截断）：

- **倍率**：微信设 `×50`，当天真实走 1,000 步 → 约 50,000 步；若今日上限为 20,037，则最终只增长到 20,037。
- **增加**：QQ 设 `+10,000`，当天真实走 1,200 步 → 约 11,200 步。这 10,000 是当天的一次性偏移，不是每收到一次传感器事件就加一次。
- **自动**：支付宝设 `5,000`，按回调依次增加 0、5,000、10,000……累计到今日上限后保持不变；真实走多少步不影响这条曲线。界面辅助文案写的是「每次 +5,000 步」，但按当前实现每次回调的增量是递增的（0、N、2N…），实际数值请以诊断页的计算结果为准。
- **固定**：微博设 `50,000`，当天的上报值 = 前一天结转的绝对计数 + 50,000；全新安装或重置后约等于 50,000。

数值输入支持手动输入、快捷档位和 `− / +` 按钮（长按连续调整）；倍率档位为 ×10 / ×50 / ×100 / ×500，其他方式为 5,000 / 10,000 / 20,000 等。切换方式后原数值会保留，并按新方式的取值范围收敛。

## 五、每日上限与跨天语义

- **上限限制的是「当日新增」**，不是传感器上报的绝对计数。真实上限 =「基础上限」+ 按本地日期算出的 0–100 随机浮动（同一天里应用和 Hook 得到相同结果），首页「每日上限」一行显示的就是今日实际值；展开后可见「基准 N」和「今日 +M」。例如基础上限 80,000，今天可能是 80,037。
- **每个本地自然日重新结算**：零点后重新记录当天真实步数基线，昨日最后的上报值原样结转为今天起点，所以传感器值不会回跳；目标应用自己计算的「今日步数」则从 0 重新开始增长，直到当日上限。自动方式的回调计数也在跨天时清零。
- **中途调低上限**：立即生效，上报值停止增长，但不会倒退——目标应用通常把计数回退当作传感器重置并冻结显示，因此保护逻辑会沿用上一次的上报值。
- **重启与传感器重置**：设备重启会通过 `elapsedRealtime()` 识别，并把开机以来的步数折进当天进度；传感器绝对计数意外回退时会以新读数重设基线，当天已累计的增量保留。
- **持久化**：当日基线、额度、进度保存在**目标应用私有**的 `sporteditor_daily_state` 中，目标应用进程重启或设备重启后继续累计；旧版本状态会在首次使用时迁移。清除目标应用数据或重装应用会重置这条进度。
- **绝对计数上限**：上报值逼近 9,999,999 时，次日会从 0 重新开始一次（目标应用会把它当作传感器重置）；这是为了避免目标应用自身的计数溢出。
- **时区/日期大幅跳变**可能让当天基线提前或推迟重置。

## 六、实时生效与持久化

- 设置写入 LSPosed Remote Preferences（组名 `sport_editor_settings`），目标进程通过监听配置变化在运行中应用新规则，**通常不需要重启目标应用**。
- 但 Hook 本身在进程启动时安装：首次激活模块、更新模块、或框架热更新被拒绝时，仍需要强行停止并重新打开目标应用。
- 框架服务未连接时，配置暂存在本应用的 `local_settings`；重连后只把编辑过的目标应用同步到远程，不会覆盖未改动的远程配置。日志采集等级的选择也会在重连后补同步。
- 本应用自身不备份这些数据（`allowBackup=false`）；清除本应用数据会丢失本地暂存设置。

## 七、设置项

从首页顶栏右侧的设置按钮进入「设置」页：

| 设置项 | 可选项 / 行为 | 默认值 |
| --- | --- | --- |
| 语言 | 简体中文 / English，切换后界面立即更新 | 简体中文 |
| 主题 | 跟随系统 / 浅色 / 深色 | 跟随系统 |
| 动态取色 | 跟随壁纸配色；仅 Android 12（API 31）及以上显示此开关 | 开启 |
| 诊断 | 打开诊断页，查看环境、目标应用与日志 | — |
| 更新 | 手动检查 GitHub 上的最新 Release | — |
| 项目主页 / 许可证 | 打开项目仓库和 MIT 许可证页面 | — |

应用内**没有独立的动画开关**：界面动效跟随系统的「移除动画」无障碍设置和开发者选项中的动画缩放。

「更新」只会检查并跳转到 Release 页面，不会自动下载安装。检查使用公开的 GitHub Releases API，超时 10 秒；失败时显示错误原因并可点「重试」，无新版本时显示「已是最新版本」，有新版本时显示版本号和「更新」按钮。

## 八、诊断与常见问题排查

### 诊断页

「设置 → 诊断」有三个页签：

- **环境**：应用版本与构建类型、Android 版本、设备、框架名称/版本、连接状态，以及目标应用启用数、已安装数和日志条数（缓冲上限 500 条）。
- **目标应用**：各应用的安装与启用状态、当前规则摘要；展开后显示包名、`enabled=… mode=… value=… max=…`，以及最近传感器事件的 `raw → reported`、相对时间和计算摘要（`delta`、`incr`、`limit`、`day_start`、`base`、`auto`、`rollover`、`held`）。有事件但步数不对时，先看这里。
- **日志**：按类型（框架 / 配置 / Hook）、等级（信息 / 警告 / 错误）筛选，支持关键词搜索、复制、分享和清空（二次确认）。「日志采集等级」可随时调低/调高，目标进程运行中也会跟随。分享报告只包含最近 100 条并会注明截断。页面底部还提示完整日志可用 `adb logcat -s SportEditor` 查看，框架日志在 LSPosed / Vector 管理器的「日志」中。

### 常见问题

| 现象 | 排查顺序 |
| --- | --- |
| 首页显示「未连接」 | 确认模块已在 LSPosed 中启用、作用域已勾选目标应用；重启本应用；核对框架版本是否支持 API 101/102（官方 1.9.2 不支持） |
| 已连接但目标应用步数不变 | 确认该应用开关已打开；首次启用/升级模块后强行停止并重新打开目标应用；确认目标应用已安装且读取计步传感器；到诊断页看是否收到传感器事件 |
| 微信 / 支付宝看不到运动数据 | 这两个应用通常需要登录账号；先确认应用内本身能显示运动页面 |
| 步数到上限后不再增长 | 这是当日增量封顶的预期行为；次日会重新累计 |
| 调低上限后显示没有减少 | 保护逻辑刻意避免计数回退；已上报的当日步数不会撤回 |
| 跨天后绝对步数没有归零 | 上报值保持连续是刻意设计；目标应用自己计算的「今日步数」会重新从 0 增长 |
| 微信里找不到「固定」 | 微信运动按增量同步，固定值无效，界面已隐藏该选项 |
| 清除目标应用数据后进度丢失 | 每日基线保存在目标应用私有存储中，清除数据或重装会重置 |
| 检查更新失败 | 确认设备能访问 `api.github.com`；检查失败不影响步数修改，可稍后重试 |
| 诊断页没有日志 | 重启目标应用或改动一次设置即可产生日志；确认采集等级没有过滤掉信息级日志 |

> **测试限制**：模拟器没有真实计步传感器，无法验证真实步数改写；完整的模拟器验证环境见 [模拟器测试](emulator-test.md)。
